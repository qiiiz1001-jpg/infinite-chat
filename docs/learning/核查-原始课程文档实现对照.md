## 4. 必要修正和等价重构

- 原文逐步覆盖同一个类，早期 run/destroy、连接增删方法等整合为 start/stop、bind/unbind；握手成功后绑定，避免先发布未认证连接。单聊/群聊推送合并在消费分支，AI 回复独立消费，防止多节点重复调用模型。
- 原文带参数的 helper 并非全部保留同名方法，例如群组创建从 SessionService 整合到 GroupService、昵称映射和历史日志在对应业务方法内完成。接口能力与返回契约保留，不靠保留空壳旧方法凑数。
- 原文第 9.6.6 的缓存优先主线此前被改成每次查库，2026-10-31 已纠正：七天内 Redis 够一页且页尾排序明确时直接返回，不查消息表；不足/异常才按原始游标查 MySQL，冷数据直接查库。保留回源边界修正，避免原文直接跳到七天前漏掉热区缺口；14 项消息测试含零消息表查询断言。缓存仍异步，不承诺完整性或强一致。
- 业务身份取当前认证用户，内部 RPC 加内部认证；保留角色锁、红包 ready 门禁、唯一领取约束、冻结退款等修正，不恢复原文的越权和一致性缺陷。
- 通知在群事务提交后发送。建群需要返回通知失败列表时，在提交后有界等待确认；失败不撤销已提交成员。邀请、踢人、退群仍记投递失败日志，没有虚构通用 outbox。
- 阶段 SQL 合并为最终初始表与可重复升级，删除原文 DROP 操作；样例邮箱、服务器地址、密码与模型 key 参数化，不复制原文个人凭证或修改原始资料。
- 当前 Boot/Cloud/Alibaba 版本配套 Nacos 3.0.3，外置库采用[官方对应 SQL](https://github.com/alibaba/nacos/blob/3.0.3/distribution/conf/mysql-schema.sql)，保留许可与来源指纹，不把旧版本库直接套入新镜像。

## 7. 2026-11-01 第四轮：领取返回与 Lua 终态顺序

核对原文 13.5 的五键授权/重复领取/空池/不存在/成功返回，以及 13.6—13.7 详情、统计、金额转换和查询顺序。详情和统计未发现本轮需改动的业务偏离，保留既有阅读授权与分页参数校验。

发现并修复两项脚本顺序问题：

- 原文优先检查领取记录，当前新增的 ready/时钟检查却排在前面，导致到期后或 grant 缓存消失时，已领用户取不到原金额。现先识别已有领取记录，Java 继续读取该用户原金额；门禁仅拦截新的取钱。
- 无条件按 expiresAt 判断过期，会遮蔽已存在的“已领完”墓碑。现在既有终态优先，无终态时才按时钟判断到期。

17 个实际 Lua 脚本执行场景通过（Lupa 引擎，Redis 命令为内存桩），公共/红包 10 项 Java 测试重跑及打包通过。可复查[脚本测试](../../tools/test-redpacket-lua.py)和[场景结果](../receive-lua-results.json)。未启动真实 Redis，不把这类测试解释为已验证 Redis 并发原子性或 TTL 调度。
