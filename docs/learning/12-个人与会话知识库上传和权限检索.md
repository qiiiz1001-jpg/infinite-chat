# 12：个人与会话知识库——上传、索引与权限检索

[学习导航](00-学习导航.md) · [上一篇：消息与提醒](11-Agent会话消息与定时提醒.md) · [验证记录](../verification.md)

## 本篇目标

沿当前源码理解“用户上传自己的资料 → 明确共享范围 → 后台索引 → 当前会话按权限检索 → 带来源回答”的完整业务链。2026-11-20 用户授权的课程外升级，改在 IM 工程；原始课程资料和独立 AI 工程未修改。

本次把普通用户对话从旧共享示例库切换到用户上传的资料库。个人资料与会话资料都有明确归属；资料不会因为上传过，就自动对整个系统可见。

## 1. 先看三个使用场景

**个人学习：**你上传简历、面试笔记，选择“我的个人知识库”，在本人的助手会话问“根据我的简历整理一段项目介绍”。这类资料只允许本人读取，只能进入本人的助手问答上下文。

**团队协作：**项目群成员上传接口说明，选择该群的“会话知识库”。当前有效成员都可以查询；另一个群即使有同名文件，也不会混入检索。退出群后，不能继续预览或检索该群资料。当前约定是所有有效成员可上传，只有上传者且仍有访问权时可以删除、重试自己的文件；没有额外实现群管理员资料管理。

**查资料后办事：**在[资料页面](../../GateWay/src/main/resources/static/knowledge.html)选择项目群查到接口要求，再进入[消息与提醒页面](../../GateWay/src/main/resources/static/agent-console.html)，用相同问答会话要求“根据当前资料拟一条通知”。Agent 使用当前范围的检索工具和上一篇的消息工具；发消息仍需明确确认。页面跳转只携带会话 ID，不携带 Token，进入另一页面需重新登录。个人提醒仍须选择本人的助手会话。

## 2. 范围规则先记清

| 当前操作 | 可以访问什么 |
|---|---|
| 个人资料列表、预览、删除 | 本人上传的个人资料；不接受客户端指定其他 ownerId |
| 本人助手会话问答 | 本人个人资料＋该助手会话的共享资料 |
| 普通单聊、群聊问答 | 仅当前会话的共享资料，不加入个人资料 |
| 会话资料列表、预览 | 当前有效会话成员；上传者退群后也不能继续访问 |
| 会话资料删除、索引重试 | 上传者本人，且仍有当前会话访问权 |

这里的“个人”由后端从登录态确定；“当前会话”也必须经过成员授权。模型提示词和前端下拉框不负责最终授权。

先看[KnowledgeAccess.context / space](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeAccess.java)，它通过[SessionAccessClient.knowledgeAccess](../../AiService/src/main/java/cn/qingliao/aiservice/client/SessionAccessClient.java)请求 UserService。[UserSessionController.knowledgeAccess](../../UserService/src/main/java/cn/qingliao/userservice/controller/UserSessionController.java)同时检查用户状态、会话状态、有效成员；只有 type=2、本人和固定 AI_ID 两名有效成员的会话才允许带入个人资料。RPC 失败直接拒绝，不能降级成公共资料库。

## 3. 文件夹、字段和函数名怎么读

| 名字 | 含义与入口 |
|---|---|
| [KnowledgeController](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeController.java) | 上传、列表、预览、删除、重试、检索和问答 HTTP 入口 |
| [KnowledgeService](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeService.java) | 先授权，再调用解析与存储；Readable 表示可读取 |
| [KnowledgeParser](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeParser.java) | Parser：解析器；把上传文件提取成文字 |
| [KnowledgeIndexer](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeIndexer.java) | Indexer：索引构建器；分片、生成向量、提交完整索引 |
| [KnowledgeRepository](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeRepository.java) | Repository：数据库访问；负责条件领取、事务和两路检索 SQL |
| [ScopedKnowledge](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/ScopedKnowledge.java) | Scoped：限定范围；绑定用户/会话后检索、融合、精排 |
| ownerId / scope / sessionId | 所有者 / PERSONAL 或 SESSION 归属 / 共享会话编号；个人资料内部用 sessionId=0 |
| documentId / chunk / embedding | 文件编号 / 切分片段 / 语义向量；片段通过 documentId 继承文件权限 |
| claim / lease / heartbeat / revision | 条件领取 / 租约 / 延长租约 / 资料版本；处理重启、长调用和记忆隔离 |

新表是 PostgreSQL 的 kb_document、kb_chunk，见[03-scoped-knowledge.sql](../../database/postgres/03-scoped-knowledge.sql)。没有把资料表建到 MySQL；会话与成员仍以 UserService 的 MySQL 数据为准。旧 chat_embeddings 是课程示例/受限评测数据，不自动推断为某个人或某个群的资料。

## 4. 第一条链：上传到资料可检索

1. [knowledge.html 的 upload 事件](../../GateWay/src/main/resources/static/knowledge.html)发送 multipart 文件，选择 PERSONAL 时不传 sessionId，选择 SESSION 时必须选择会话并确认共享。前端不提交 ownerId。
2. [KnowledgeController.upload](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeController.java)从 `CurrentUser.id()`取得身份，交给[KnowledgeService.upload](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeService.java)。它在解析前、落库前分别验证范围，避免直接沿用耗时解析之前的权限。
3. [KnowledgeParser.parse](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeParser.java)支持 UTF-8 TXT、Markdown、文字型 PDF、DOCX。限制文件 10MB、文字 20 万字符，PDF 最多 300 页；DOCX 限制解压条目及大小，并禁用 DTD/外部实体。不支持扫描 PDF 的 OCR、旧 DOC、图片和电子表格。
4. [KnowledgeRepository.create](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeRepository.java)保存提取文字、归属和 SHA-256，状态 PENDING。同一上传者、同一范围、同一文件内容重复上传返回原记录；不同会话或不同用户独立。原始二进制不长期保存，目前的预览是提取文字，不是原文件下载。
5. [KnowledgeIndexer.tick / index](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeIndexer.java)默认每 3 秒领取一个任务。条件更新成 INDEXING，生成独立租约；按最多 1200 字符、重叠 150 的递归策略切分，每批最多 16 段调用 Embedding，整个文件最多 256 段。当前库向量维度固定 1024。
6. [Repository.complete](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeRepository.java)在一个 PostgreSQL 事务里锁住文件，检查租约，保存全部片段并改 READY。中途失败不留下半份可检索资料；FAILED 文件可以由上传者手工重试。

```text
用户文件 → 范围授权 → 解析文字 → kb_document:PENDING
  → 后台条件领取 INDEXING → 分片 / Embedding
  → PostgreSQL事务：全部kb_chunk + 文件READY
  → 才能参与当前范围问答
```

调度器恢复过期的 5 分钟租约，正常批次执行前会 heartbeat 延长租约；累计领取达到 3 次后超时恢复为 FAILED。模型或数据库调用失败会直接标 FAILED，由用户核对配置后重试；这不是所有失败都无限自动重试。重启不会丢掉已落库的 PENDING 任务。

## 5. 第二条链：提问到带来源回答

资料页提供[KnowledgeController.search / ask](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeController.java)。search 返回片段和文件来源；ask 先检索，再让模型依据这些片段回答，返回 answer 与结构化 sources。没有命中时直接返回缺少依据，不调用回答模型。

主要入口是[ScopedKnowledge.retrieve](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/ScopedKnowledge.java)：

1. 用可信 userId、当前 sessionId 重新取得有效成员权限，判断能否带入个人资料。
2. [Repository.vectors](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeRepository.java)对问题生成的向量执行 pgvector 余弦距离排序；[Repository.keywords](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeRepository.java)执行当前库的 BM25 查询。两路 SQL 都先限定 READY、当前会话或本人个人资料，再排序和 LIMIT。
3. [HybridContentRetriever](../../AiService/src/main/java/cn/qingliao/aiservice/rag/retriever/HybridContentRetriever.java)按 RRF 融合，最多 20 条候选；[RerankingContentRetriever](../../AiService/src/main/java/cn/qingliao/aiservice/rag/retriever/RerankingContentRetriever.java)精排，最多保留 5 条。文件名、documentId、片段号随内容一起保留。
4. 精排可能经过外部网络，返回前再次检查成员与文件状态；删除或失去权限的资料不返回。
5. ask 让模型基于参考资料作答并引用来源，页面按纯文本显示答案及片段。sources 表示实际检索来源，不保证模型对每个来源都作出了正确引用，答案质量仍需真实模型评测。

基础 pgvector 镜像没有 pg_search 时，关键词分支退回到**相同权限条件**的子串匹配，中文也可按连续字面内容匹配；这时不能声称仍在执行 BM25。Embedding 查询失败时可以使用关键词结果，但首次上传必须成功完成索引才会 READY。精排失败沿用原有受限候选降级，不会绕开权限。

**为什么不能检索完所有人的资料再过滤？**别人的片段可能已经发给精排模型，也可能占满 Top K 导致本人资料召回不到。因此范围条件必须在两路 SQL 中存在；返回前的复核只是额外处理等待期间的变更，不是主要权限机制。

## 6. 与 Agent、聊天记忆怎样连接

看[AiChatService.forActor](../../AiService/src/main/java/cn/qingliao/aiservice/ai/AiChatService.java)：每次请求绑定 userId、sessionId，装配当前范围的自动检索和[ScopedRagTool.searchKnowledge](../../AiService/src/main/java/cn/qingliao/aiservice/tool/ScopedRagTool.java)。模型没有 ownerId 参数，工具换线程仍使用同一可信身份；消息与提醒工具继续沿上一篇执行。

Redis 记忆使用 `kb-v2:用户:会话:可见READY资料版本`。个人/群聊、不同用户的记忆不混用；新增完成索引或删除资料后会生成不同版本，后续请求不加载旧资料集的回答和工具结果。自动召回原文还通过 `storeRetrievedContentInChatMemory(false)`避免直接持久化到记忆。资料版本变化会切换对话记忆，这是当前实现的取舍。

**删除不等于撤回所有已输出内容。**[Repository.delete](../../AiService/src/main/java/cn/qingliao/aiservice/knowledge/KnowledgeRepository.java)将文件置 DELETED、清空提取文字并删除片段，旧索引持有者无法提交复活；旧 Redis 命名空间等待已有 TTL 清理。已经生成的 IM 消息、浏览器中已读的内容及进行中的外部模型请求不可能靠一次删除收回。

旧 `/api/ai/insert` 已停用，页面原来的“维护共享知识库”也替换为上传入口。[kb-curator Skill](../../AiService/src/main/resources/skills/kb-curator/SKILL.md)引导用户明确选择范围上传，不再让模型调用旧共享写入工具。旧[RagConfig](../../AiService/src/main/java/cn/qingliao/aiservice/config/RagConfig.java)、样例文件和 RagTool 保留作课程参考；普通用户对话不挂载旧 RagTool。旧 dev/test 评测入口额外要求维护者登录，不能用于读取所有用户上传的资料。

## 7. 启动与实际验证

1. 在 `.env` 的 **PGVECTOR_DATABASE 对应 PostgreSQL 库**执行[03-scoped-knowledge.sql](../../database/postgres/03-scoped-knowledge.sql)。不要执行到 MySQL。默认库名 chat_vectors，具体按当前配置。新空卷初始化已接入普通/服务器 Compose 和整合 Compose 的初始化目录；已有卷必须手动执行迁移。
2. 运行 `./tools/verify.ps1 -Package`，使用新 Jar 重启 UserService、AiService、GateWay。开启 `rag.indexing.enabled`（默认 true），配置真实可用的 Embedding；问答还需要 ChatModel，精排使用现有配置。现有整合脚本的 `-Models` 模式加载模型，已停止自动导入旧课程文档。
3. 打开 `http://localhost:10010/knowledge.html`，用现有邮箱和密码登录。先上传个人笔记，等待 READY，在本人助手会话检索；再用另一个用户登录，确认不能读取。向项目群上传另一份资料，用该群问答，确认不会混入个人资料。
4. 再试索引失败重试、删除、退出群后的拒绝，并从资料页进入 Agent，选择相同会话拟消息。模型选择工具和回答质量需要真实配置后验证，不能把替身答案当成模型验收。

本轮 JDK 17 标准脚本 103 项回归通过，六应用打包通过；另在真实 PostgreSQL/pgvector/pg_search 的独立随机 schema 跑 6 项测试，全部通过并清理临时 schema。真实 HTTP multipart 上传、文档表、分片事务、权限范围查询、删除和重试实际执行，模型/Embedding、Redis身份验证及会话 RPC 是替身；UserService 的成员/会话状态规则另用 HTTP/H2 验证。浏览器用模拟接口验证上传、范围选择、来源显示、预览、删除/重试、大整数与退出清理。详细证据见[验证记录](../verification.md)。

测试入口：[KnowledgeParserTest](../../AiService/src/test/java/cn/qingliao/aiservice/KnowledgeParserTest.java)、[ScopedKnowledgeTest](../../AiService/src/test/java/cn/qingliao/aiservice/ScopedKnowledgeTest.java)、[ScopedKnowledgePgTest](../../AiService/src/test/java/cn/qingliao/aiservice/ScopedKnowledgePgTest.java)、[AgentActionHttpTest](../../UserService/src/test/java/cn/qingliao/userservice/agent/AgentActionHttpTest.java)。PostgreSQL 测试需显式设置 `RUN_KNOWLEDGE_PG_TESTS=true` 并加载当前数据库环境，不在默认标准测试脚本中自动连接外部库。

本轮未对实际业务 schema 安装迁移或重启旧服务，未调用真实模型/Embedding/精排 API。当前没有 OCR、原文件下载、文档版本编辑、管理员接管、无限量文件分页和存储配额；列表显示当前范围最近 100 个未删除文件。已有 READY 资料可以从关键词降级受益，不表示没有 Embedding 配置也能索引新文件。

## 本篇自查

1. 群成员上传了一份文件，其他群成员为什么能查，其他群为什么不能查？
2. 自己上传的简历能不能自动进入项目群问答？
3. 删除文件时后台还在生成向量，会不会重新插入片段？
4. 为什么资料内容变化后还要切换聊天记忆？
5. PostgreSQL 测试通过，是否代表真实模型回答已经正确？

## 自查解答

1. 文件归属 SESSION 和具体 sessionId，查询前检查当前成员，SQL 再限定当前会话。不是按文件名或模型指令区分。
2. 不能。个人资料只有本人助手上下文允许进入；要共享需用户明确上传到群的会话知识库。用户主动确认发出的消息属于另一次明确共享操作。
3. 删除与索引提交锁住同一文件行；提交还要匹配 INDEXING 和 leaseToken。已删除或被新租约替换的旧执行者不能复活文件。
4. 即使新检索正确，旧模型回答和工具结果也可能含有已删除资料。按资料版本切换记忆，后续请求不再加载这份旧上下文；已输出的历史消息不能因此撤回。
5. 不能。测试实际验证 SQL、HTTP 和状态竞争，但模型/Embedding 用替身，真实检索效果、回答引用与工具选择仍需模型联调和评测。
